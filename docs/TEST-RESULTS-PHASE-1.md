# Phase 1 Test Results

Test cases as defined in Section 6.2 of `docs/Fieldnote_Phase_1_Plan.md`. Per Section 6.2.6: a failing test isn't a disaster, an _unrecorded_ one is — so every row below is either a real result or honestly marked as not yet run, never left blank.

**Status as of 2026-08-28:** code complete for Phase 1's scope; verified by typecheck, lint, and a live pass through the running `npm run web:coi` web preview (see `docs/DESIGN.md` D-014). That pass gave real, live-verified results for the test cases that are about navigation, filtering, empty states, theming, and validation — because those run through the exact same screens and components no matter what's underneath. It could **not** verify anything that depends on the real on-device SQLite database, because the web preview in this environment can't open one at all (D-010) and falls back to an in-memory mock store instead (D-013) — that store is seeded with a handful of rows, never persists across a reload, and is explicitly not a stand-in for real device persistence. Those rows remain **Not yet run**, and still need a real pass on a physical phone or emulator before Phase 1 can be called done, per Section 0.6.5 of the plan.

**Result key:** **Pass** — verified against real code/schema without running the app. **Pass (web preview)** — actually clicked through and observed live in the running web preview, against the in-memory mock store; proves the UI/navigation/validation logic works, does **not** prove real SQLite persistence. **Not yet run** — needs a physical device or emulator, or (a few rows) is structurally impossible to check through the web preview's mock data, explained in the notes.
